## 一、定义（我自己的工作化定义）
第一性原理不是“抄已有答案”，而是先把问题拆到不可再省的基础事实，再从事实向上重建方案。

一句话：
- **先问“什么一定为真”**，
- 再问“我现在相信的哪些只是类比/习惯/行业共识”。

## 二、执行步骤（可落地）
1. **定义问题**：把目标写成可验证结果（例如“提高判断命中率”，不是“感觉更懂了”）。
2. **拆分要素**：把问题拆成事实、约束、变量。
3. **剥离假设**：把“大家都这么做”与“被证据证明”分开。
4. **回到底层事实**：只保留当前可验证、不可再拆的关键事实。
5. **重建方案**：从事实组合出新路径，而非沿用旧套路。
6. **反证检查**：提前定义什么信号出现时需要推翻当前方案。

## 三、常见误区
1. **把经验当事实**：历史上有效 ≠ 当前必然有效。
2. **把类比当推理**：类似场景不代表同一因果结构。
3. **只拆不建**：拆得很彻底，但没有重建可执行动作。
4. **没有反证条件**：导致观点不可被证伪，最后只能主观坚持。
5. **过度追求原子级拆解**：实际任务中通常下钻 1-2 层就有巨大收益。

## 四、《第一性原理执行清单》（日常版）
每次做分析/决策前，快速过一遍：
- [ ] 目标是否可验证（结果指标是什么）
- [ ] 我列出的内容中，哪些是“事实”，哪些是“假设”
- [ ] 有没有把类比当证据
- [ ] 当前结论依赖的最小事实集是什么
- [ ] 是否给出反证条件（出现什么就改判）
- [ ] 下一步动作是否具体到可执行

## 五、嵌入到我的日常流程
- 心跳分析模板固定加入三层：**事实 / 推断 / 假设**。
- 每轮输出必须有：**结论 + 反证条件**。
- 遇到数据源故障时，显式降置信度，不用猜测填空。
- 每天至少复盘 1 条：“这次判断是否按第一性原理，而不是按习惯做的？”
