## 2026-03-19 04:17 心跳学习（OpenClaw 调度）
- Heartbeat 适合“可容忍轻微漂移”的批量巡检（邮箱/日历/通知），能复用主会话上下文并降低 API 调用。
- Cron 适合“精确时点 + 隔离上下文 + 模型覆盖”的任务；尤其是定点推送、一次性提醒、重分析任务。
- 混合策略最佳：Heartbeat 做常规感知，Cron 做准点输出；避免把所有定时任务都塞进同一种机制。

## 2026-03-19 04:48 心跳学习（openclaw status 诊断）
- `openclaw status` 适合快速看渠道与会话健康；`--all` 给更完整可粘贴诊断快照。
- `openclaw status --deep` 会做实时探测（WhatsApp/Telegram/Discord/Google Chat/Slack/Signal），适合排查“在线但收不到消息”。
- 状态总览会显示版本更新提示（含 git SHA / update hint），可作为日常健康巡检入口。

## 2026-03-19 05:18 心跳学习（Gateway 健康排查链路）
- 排查优先顺序可固定为：`openclaw status` → `openclaw status --deep` → `openclaw health --json`，逐级加深，避免一上来重操作。
- 对话面可直接发 `/status` 获取状态回显，适合“先确认再排障”。
- 日志关键关键词：`web-heartbeat` / `web-reconnect` / `web-auto-reply` / `web-inbound`，能快速定位链路断点。

## 2026-03-19 06:48 心跳学习（Cron 覆盖与投递）
- Cron 的模型/思考级别覆盖优先用于 isolated 任务；main-session 覆盖会改变共享会话模型，易造成上下文漂移。
- 隔离任务投递可用 `delivery.mode` 三态：`announce`（发消息）、`webhook`（HTTP 回调）、`none`（仅执行不投递）。
- Telegram 主题投递建议 `chatId:topic:threadId` 显式格式，减少目标歧义。

## 2026-03-19 07:18 心跳学习（会话隔离与安全）
- 多人 DM 场景下默认 `dmScope: main` 有上下文串线风险，推荐 `per-channel-peer` 或 `per-account-channel-peer`。
- 同一联系人跨渠道需要会话合并时，用 `session.identityLinks` 做身份映射，避免错误共享或割裂。
- 大规模会话建议开启 `session.maintenance.mode: enforce` 并同时设 `pruneAfter + maxEntries`，避免会话文件长期膨胀。

## 2026-03-19 07:48 心跳学习（security audit）
- `openclaw security audit` 可作为常规安全体检；`--deep` 适合上线前/变更后深检，`--json` 适合 CI 或策略门禁。
- 多人 DM 共享主会话会被审计提示，推荐 `session.dmScope=per-channel-peer`（多账号场景可用 per-account-channel-peer）。
- `--fix` 只做可预测硬化（如 groupPolicy、日志脱敏、敏感文件权限），不会替你做高风险变更（如关工具/改网络暴露/轮换密钥）。

## 2026-03-19 08:18 心跳学习（sessions cleanup）
- `openclaw sessions cleanup --dry-run` 可先预览清理影响（含逐会话动作表），适合变更前评估。
- `--enforce` 可在 maintenance.mode=warn 时强制落地，适合积压已确认后的一次性清理。
- 会话清理只处理 sessions/transcripts，不处理 cron run logs；后者需走 cron.runLog 配置。

## 2026-03-19 08:48 心跳学习（channel 配置护栏）
- `channels.<provider>.groupPolicy` 缺失时运行时默认回退到 `allowlist`（fail-closed），是安全优先设计。
- `channels.modelByChannel` 仅在“会话未被 `/model` 等显式覆盖”时生效，适合按频道定制模型。
- Telegram 频道模型可细到 topic 级（`chatId:topic:threadId`），便于同群不同线程差异化成本/质量策略。

## 2026-03-19 09:18 心跳学习（Remote over SSH）
- 远程架构原则：只保留一个 Gateway 作为状态真源；节点仅做外设，不承载会话主状态。
- 远程诊断优先链：先 SSH 隧道 `-L 18789:127.0.0.1:18789`，再用 `openclaw status --deep` / `openclaw health`。
- 传 `--url` 时 CLI 不再从配置/环境自动兜底凭据，需显式带 `--token` 或 `--password`。

## 2026-03-19 10:48 心跳学习（安全审计高危面）
- `open_groups + elevated/runtime/fs` 是高危组合，最容易形成提示注入到高权限执行链路，需优先收敛 groupPolicy 与工具面。
- Control UI 在非 loopback 场景必须显式 `allowedOrigins`；依赖 host-header 回退是安全降级，会被审计告警。
- `dangerous/dangerously` 配置项应视为“临时断路器”，启用后应有回滚时限与复检动作，避免常驻风险。

## 2026-03-19 11:18 心跳学习（Heartbeat 响应契约）
- `HEARTBEAT_OK` 仅在“无事项”时返回；若前后附加内容在 `ackMaxChars` 内，平台仍可能按 ack 折叠。
- 有告警时不要混入 `HEARTBEAT_OK`，应只输出告警正文，避免被系统误判为静默确认。
- 若需更精细行为，应改 heartbeat.prompt（逐字下发）而不是在临场推断旧任务。

## 2026-03-19 11:48 心跳学习（自动化故障排查）
- 调度故障排查建议走固定命令梯：`status -> gateway status -> logs --follow -> cron status/list/runs -> heartbeat last`，避免漏层级。
- “任务执行但没消息”常见不是执行失败，而是 `delivery.mode=none` 或 channel/to 目标缺失。
- heartbeat 常见静默原因可先查：`quiet-hours`、`requests-in-flight`、`alerts-disabled`、`empty-heartbeat-file`。

## 2026-03-19 12:18 心跳学习（时区一致性）
- `envelopeTimezone` 默认用主机本地时区；跨机部署时可改为 `user` 或显式 IANA，减少“消息时间看起来错位”。
- `agents.defaults.userTimezone` 未设置时会运行时回退主机时区，不会自动写配置文件。
- 工具返回保留原始时间戳，同时补充 `timestampMs/timestampUtc` 归一字段，便于跨渠道统一比较。

## 2026-03-19 12:48 心跳学习（openclaw doctor）
- `openclaw doctor --repair` 会先备份配置到 `~/.openclaw/openclaw.json.bak`，并清理未知键，适合“修完还能回滚”。
- 无 TTY（如 cron/聊天触发）时交互修复会被跳过；这类场景应优先使用非交互可执行项。
- doctor 现支持检测会话目录孤儿 transcript，可归档为 `.deleted.<timestamp>`，实现可追溯清理。

## 2026-03-19 13:18 心跳学习（gateway CLI）
- `openclaw gateway` 默认要求 `gateway.mode=local`，临时调试可用 `--allow-unconfigured`，避免误把临时环境当生产配置。
- 诊断优先用 `gateway status`（服务态+可选探测）与 `gateway probe`（同时探测 remote + localhost）。
- 当显式传 `--url` 时必须显式带鉴权（`--token/--password`），否则不会从配置自动兜底。

## 2026-03-19 13:48 心跳学习（channels CLI）
- `openclaw channels capabilities` 可先做能力面探测（意图/权限/特性），比盲测消息发送更高效。
- 多账号接入时，单账号顶层配置会迁移到 `accounts.default` 以保持行为一致；混合态可用 `openclaw doctor --fix` 收敛。
- 排障链可固定：`channels status/list/logs` + `status --deep` + `doctor`，先确认链路和权限，再动配置。

## 2026-03-19 14:18 心跳学习（Gateway 深度排障）
- 排障先查“路由/策略”再查“重连/重启”，可避免把策略拦截误判为通道掉线。
- `gateway status --deep` 可比普通状态多看服务层配置差异（cli/service）与系统服务态，适合“看起来在线但不工作”。
- 常见硬阻断签名：`gateway.mode!=local`、非回环绑定但无鉴权、端口冲突（EADDRINUSE）；定位后再改配置。

## 2026-03-19 14:48 心跳学习（按渠道故障签名排障）
- “已连接但不回复”要先按渠道看故障签名（pairing/mention/allowlist/scopes），再决定是否重登。
- 群聊静默常见根因不是断连，而是 `requireMention`、bot privacy mode 或 groupPolicy/allowlist 拦截。
- Telegram/Slack 等平台排障先查权限与策略，再查网络；可显著减少无效重启与重复登录。

## 2026-03-19 15:48 心跳学习（配置治理）
- 配置校验是严格模式：未知键/类型错误会阻止网关启动；故障态下优先用 `doctor/logs/status` 做诊断。
- 配置缺失时系统有安全默认值，可先小步增量配置，避免一次性大改引入多处失配。
- 配置调整优先走 `openclaw config set/get/unset` 或 configure 向导，降低手改 JSON5 出错率。

## 2026-03-19 16:18 心跳学习（模型认证与凭据）
- Anthropic 场景优先 API Key；`setup-token` 适用于订阅凭据，但某些 token 仅限 Claude Code，遇权限错误应切回 API Key。
- 网关守护进程场景建议把密钥放 `~/.openclaw/.env`，避免“命令行可用、服务进程不可用”的环境继承问题。
- 自动化巡检可用 `openclaw models status --check`：过期/缺失返回码 1、临近过期返回码 2，便于 cron 告警分级。

## 2026-03-19 16:48 心跳学习（logs CLI）
- `openclaw logs` 通过 RPC 拉取网关文件日志，远程模式也可直接用，不必先 SSH。
- 日志排查常用组合：`--follow` 持续追踪 + `--json` 便于后续脚本过滤。
- `--local-time` 可将时间戳转为本地时区，跨时区排障时更容易与会话时间线对齐。

## 2026-03-19 17:18 心跳学习（日志体系总览）
- 网关默认文件日志在 `/tmp/openclaw/openclaw-YYYY-MM-DD.log`，日期按网关主机本地时区滚动。
- `openclaw logs --follow` 是统一入口；需要自动处理时可加 `--json` 获取 type-tagged 事件流（meta/log/notice/raw）。
- `logging.redactSensitive` 仅影响控制台输出，不会改写文件日志；安全审计需同时关注文件落盘内容。

## 2026-03-19 17:48 心跳学习（Cron 核心语义复盘）
- Cron 作业状态持久化在网关侧（默认 `~/.openclaw/cron/jobs.json`），重启后不会丢计划。
- 同一计划可选两种执行路径：main 会话（随下次 heartbeat 执行）与 isolated 会话（独立 `cron:<jobId>` 运行）。
- `schedule.at` 若不带时区会按 UTC 解释；定点任务应显式时区，避免“本地时间偏移”误触发。

## 2026-03-19 18:18 心跳学习（模型选择与故障面）
- 模型选择顺序是 `primary -> fallbacks`，同一 provider 内先做凭据 failover，再切下一个模型。
- 设置 `agents.defaults.models` 会变成硬 allowlist；用户选到未入表模型会直接报“not allowed”，看起来像“没回复”。
- `/model` 适合会话内快速切换与排障；若模型 ID 自带 `/`（如 OpenRouter 风格），需带 provider 前缀完整写法。

## 2026-03-19 18:48 心跳学习（Model Failover）
- 失败处理是两级：先在同 provider 内做 auth profile 轮转，再切到 `model.fallbacks`。
- 会话默认会“粘住”已选 auth profile（提高缓存命中）；只有 reset/compaction/冷却失效时才切换。
- 账单不足类错误会触发 `disabledUntil` 长回退（5h 起步，最长 24h），不是短冷却，需按账单故障处理。

## 2026-03-19 19:18 心跳学习（OAuth 与凭据隔离）
- OpenClaw 将 `auth-profiles.json` 作为统一 token sink，可降低多端登录导致 refresh token 互踢风险。
- 凭据是按 agent 隔离存储（`~/.openclaw/agents/<agentId>/agent/auth-profiles.json`），多身份场景优先“分 agent”而不是混在一个 agent。
- OpenAI Codex OAuth 在无回调绑定条件下支持手动粘贴 redirect/code，适配远程/无头环境。

## 2026-03-19 19:48 心跳学习（模型提供商与密钥轮换）
- `agents.defaults.models` 一旦设置即成为模型 allowlist；新增 provider/model 前需先入表，否则会触发“not allowed”。
- 多密钥轮换优先级是 `OPENCLAW_LIVE_*` > `*_API_KEYS` > `*_API_KEY` > `*_API_KEY_*`，且仅在限流错误时轮换。
- OpenAI Codex 默认 `auto` 传输（WebSocket 优先，SSE 回退）；遇链路不稳可在模型参数显式指定 transport。

## 2026-03-19 20:18 心跳学习（故障分诊前门）
- `help/troubleshooting` 适合 2 分钟分诊：先跑统一命令梯，再按“症状入口”跳到深度 runbook。
- `openclaw status --all` 是可共享的全量快照，适合协同排障时减少来回追问。
- 分诊应先判定“无回复/UI连不上/网关不起/通道不流/自动化不触发”，再进入对应章节，避免混排。

## 2026-03-19 20:48 心跳学习（Date & Time 全链路）
- OpenClaw 默认“传输时间用主机本地、系统提示只给用户时区”，需要当前时刻应调用 `session_status`，不依赖提示词静态时间。
- 消息 envelope 与 system event 行使用同一时区选择逻辑；改一个维度时要同步评估两处时间语义。
- connector/tool 返回会保留 provider 原始时间，同时补 `timestampMs/timestampUtc`，跨渠道对齐应优先用归一字段。

## 2026-03-19 21:18 心跳学习（消息编排与队列）
- OpenClaw 会对入站消息做短时去重与按会话防抖，避免重连重投导致重复触发。
- 文本防抖仅对纯文本生效，媒体消息会立即 flush；控制命令默认绕过防抖保持独立执行。
- 当会话忙时可通过 `messages.queue` 选择策略（interrupt/steer/followup/collect），先定义队列语义再优化回复体验。

## 2026-03-19 21:48 心跳学习（Streaming/Chunking）
- OpenClaw 频道侧没有 token 级直推；对外是“块级消息”与“预览消息编辑”两层流式。
- 非 Telegram 渠道若要块流式，除 `blockStreamingDefault:on` 外还需显式 `channels.*.blockStreaming:true`。
- `blockStreamingBreak=message_end` 不是“永远只发一条”，超长文本仍会在结束时按 chunk 规则拆多条。

## 2026-03-19 22:48 心跳学习（Command Queue）
- 队列是“会话串行 + 全局并发上限”双层：先按 `session:<key>` 保证单会话不碰撞，再受 `maxConcurrent` 控制总体并发。
- 默认 `collect` 会把排队消息合并成一次 followup，能减少“连环继续”噪音；`steer-backlog` 则可能出现看似重复回复。
- 队列溢出可用 `drop:summarize`，把丢弃内容汇总为合成提示，避免信息直接黑洞。

## 2026-03-19 23:18 心跳学习（System Prompt 负载控制）
- `AGENTS/SOUL/TOOLS/IDENTITY/USER/HEARTBEAT/MEMORY` 会随主会话注入上下文，文件越大越容易推高上下文占用与压缩频率。
- `memory/*.md` 日记文件默认不自动注入，只在 `memory_search/memory_get` 调用时进入上下文，这是重要的 token 护栏。
- 可通过 `bootstrapMaxChars/bootstrapTotalMaxChars` 控制注入上限；出现上下文膨胀时优先治理这些文件体积。

## 2026-03-19 23:48 心跳学习（Context 可观测与降载）
- 快速排查上下文压力可用 `/status` + `/context list` + `/context detail` 三段视图，先定位大头再优化。
- 上下文不仅是对话，还包含工具 schema 与工具输出；仅精简聊天历史常常不够。
- 当窗口逼近上限时，`/compact` 是低摩擦释放手段；但根因优化仍应回到注入文件与工具负载治理。

## 2026-03-20 00:18 心跳学习（Compaction）
- 自动压缩会把旧对话摘要持久化写回会话 JSONL，不是临时内存行为；后续上下文将基于“摘要+最近消息”。
- 压缩与 pruning 区别要分清：compaction 是持久摘要，pruning 是每次请求内存态裁剪旧工具结果。
- 长会话接近窗口时可先手动 `/compact`，比等到硬触顶后被动重试更稳。

## 2026-03-20 00:48 心跳学习（Session Pruning）
- Session pruning 只在请求前对“内存上下文”裁剪旧 toolResult，不改写 JSONL 会话历史；compaction 与其作用面不同。
- `cache-ttl` 模式核心价值是减少 Anthropic 首次回暖请求的 cacheWrite 体积，TTL 过后再问更省。
- 保护边界明确：user/assistant 不动、含图片的 toolResult 不裁剪，避免多模态证据被误伤。

## 2026-03-20 01:18 心跳学习（Memory 机制）
- 记忆的真源是工作区 Markdown 文件；模型“记住”取决于是否实际写盘，而非会话内短期上下文。
- `memory_get` 对缺失文件会优雅返回空文本，不再因 ENOENT 中断流程，适合首日/新日志场景。
- 预压缩 memory flush 是“压缩前静默写记忆”机制；若会话是只读工作区（sandbox ro/none）会跳过。

## 2026-03-20 01:48 心跳学习（Token 成本与上下文）
- token 成本不只看聊天文本，系统提示、工具 schema/结果、附件与压缩产物都会计入上下文窗口。
- 成本可见性受认证方式影响：OAuth 默认只展示 token，不展示美元成本；API key 才能估算费用。
- 若模型缓存 TTL 为 1h，可将 heartbeat 设在略短于 TTL（如 55m）以减少 full prompt 重写入成本。

## 2026-03-20 02:18 心跳学习（Prompt Caching 调优）
- 缓存调优主旋钮是 `cacheRetention`，并可由 `agents.list[].params` 覆盖默认模型参数，适合分 agent 成本策略。
- `contextPruning.mode=cache-ttl` 与 heartbeat 保温应联动：TTL 后裁剪旧工具结果，心跳用于跨空档维持缓存命中。
- Provider 支持面不同：Anthropic/部分 Bedrock/OpenRouter Anthropic 支持较完整，其它 provider 可能对 `cacheRetention` 无效。

## 2026-03-20 02:48 心跳学习（Agent Workspace 边界）
- workspace 是默认 cwd 不是绝对沙箱；未启用 sandbox 时绝对路径仍可触达主机其他位置。
- `~/.openclaw/` 与 workspace 职责分离：前者放配置/凭据/会话，后者放人格与记忆文件；备份与 git 管理应区分。
- 多 workspace 并存会导致状态漂移；应保持单一活动 workspace，并让 `agents.defaults.workspace` 指向唯一真源。

## 2026-03-20 03:18 心跳学习（Slash Commands 执行面）
- 指令分两类：standalone `/command` 与 inline directives；只有“纯指令消息”会持久化会话设置。
- 指令授权遵循 `commands.allowFrom`（若配置则独占）或通道 allowlist/pairing 规则，未授权时按普通文本处理。
- 命令快速路径会绕过队列和模型（command-only + allowlisted），适合状态查询与运维命令低延迟执行。

## 2026-03-20 03:48 心跳学习（Sandboxing 边界）
- 沙箱隔离的是工具执行，不是网关本身；`tools.elevated` 仍在主机执行，会绕过沙箱保护。
- `mode=non-main` 以 session.mainKey 判定，不是按 agent id；群聊/频道会话通常属于 non-main，会进入沙箱。
- `workspaceAccess` 是关键权限阀：`none` 最保守，`ro` 禁写，`rw` 才允许直接改宿主工作区。

- 假设：把强化任务拆成“轻量固定模板”（检查→1条学习→落盘）可同时满足稳定性与低打扰。
- 方案：后续优先采用三段式执行：①固定巡检 ②单点强化（文档/复盘/小优化三选一）③双文件落盘（working-buffer + self-improvement-log）。

- 网关负责发现广播与配对决策，客户端只消费发现结果并执行连接策略。

## 2026-03-21 18:18 心跳学习（Talk Mode）
- Talk Mode 是“听→想→说”的连续语音循环，回复仍写入主会话（不是独立语音会话）。

- Bonjour TXT 记录是“未认证提示”，路由与安全决策应基于 SRV+A/AAAA 与已保存 TLS pin。
- Wide-area Bonjour 可通过 Tailscale split DNS 实现统一发现体验，适合异地节点接入。

## 2026-03-21 20:48 心跳学习（Image & Media Support）

## 2026-03-21 21:18 心跳学习（Background Exec + Process）
- 长任务应通过 `exec` 背景化并用 `process` 管理，避免主流程阻塞；`yieldMs` 决定何时自动转后台。
- `process` 会话是内存态（重启丢失），关键输出需通过 `poll/log` 拉取并沉淀到会话记录。
- 若 `process` 工具被禁用，`exec` 会退回同步执行并忽略 background/yield 参数，这点很容易误判。

## 2026-03-21 21:48 心跳学习（Sandbox / Tool Policy / Elevated）
- 三层要分清：Sandbox 决定“在哪跑”，Tool Policy 决定“能不能跑”，Elevated 仅是 exec 的宿主机逃逸通道。
- 常见误区是把 elevated 当权限放大器；实际上它不会绕过工具 deny，也不会新增工具可用性。
- 快速定位建议用 `openclaw sandbox explain` 看“实际生效配置”，比手查多层配置更可靠。
